## What this project is
Statistics system for Hajj/Umrah trips entering the "Guests of Allah service city" (مدينة خدمة ضيوف الرحمن), built for a non-profit association. Staff record trips; admins see dashboards/reports. UI is **Arabic, RTL**, minimalist white + dark green + gold.

## Owner constraints (do not break)
- **Free tools only**, no paid subscriptions, no card-required signups (for hosting/backend).
- Owner is **not a programmer**: prefer simple, well-documented, low-maintenance choices.
- All UI text Arabic. Responsive/mobile-first. Real persistence — never mock data.
- Two roles: **admin** (everything) and **entry** (add trips; see only own; no edit/delete).

## Decisions & why
- **Supabase over Firebase:** relational data + Row Level Security enforces roles in the DB (not just UI).
- **Plain static web first, then Expo:** owner had no tooling; web was fastest to ship. Business logic in `src/lib/stats.ts` is a direct port of the web version, so behaviour should match.
- **No navigation library yet:** tabs are plain state in `App.tsx`. Move to Expo Router when screens grow.
- **Worker/trip numbers:** `trip_no` comes from a Postgres sequence (`R-000001`...), generated by the DB default, never by the client.
- **Officials/services are deactivated, not deleted**, so historic trips keep their names (FK is `restrict`).
- **Admin user management** is done in the Supabase dashboard (creating users needs the service-role key, which must never ship in the app).
